## Read from the machine code

The routine takes the object in `ECX` and a pointer to three consecutive
`double` values at `[EBP+8]` (`RET 4`). It reads object minimum values at
`+0x48`, `+0x50`, `+0x58`, then maximum values at `+0x60`, `+0x68`, `+0x70`.
The minimum checks use `FCOMP`, `FNSTSW AX`, `TEST AH, 1`, `JNZ` to fail when
the point is below the face. The maximum checks use `TEST AH, 0x41`, `JZ`
to fail when the point is above the face. Thus each face is inclusive. The
minimum tests also reject unordered floating-point comparisons; the maximum
tests accept them. A point with NaN coordinates is rejected by the minimum
checks, while a NaN maximum bound can pass.

The bytes are checked independently with `tools/verify_reference.py`. The
source uses a partial object layout with an opaque prefix so known offsets
stay exact. Its C++ return type is the meaningful low byte; the original only
sets `AL`, so the other return-register bits should not be interpreted.

## Scope and unknowns

This is **READ** static behavior plus an offline original-byte differential
check, not a live game measurement. The x86 `native_point_oracle` runs the
verified 146 bytes in a separate owned test process and compares the low-byte
result with this source for 11,029 cases: all special-value combinations on
each axis and 10,000 deterministic numeric cases. All matched. The routine
contains no calls or absolute data references, allowing relocation for this
bounded check. The harness reads but does not launch or modify the installed
game. Unit tests cover
ordinary interior, all six faces, one representable value beyond each face,
quiet NaNs, and inverted bounds. The enclosing object type, remaining fields, and exact
source-level names are unknown. The caller census and native runtime
equivalence are not established by this slice.
