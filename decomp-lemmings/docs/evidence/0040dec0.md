## Read from the machine code

The helper first calls `0x0040DF30`, which forwards to the Visual Studio
2003 CRT absolute-value routine at `0x0049C8F4` (REA analysis
`ev_0ba5d90222b274dd6a6fa30678171734f0bcd2fd7202908ec4a2fd692b952273`).
If the magnitude is below the threshold, the result is zero. Otherwise a
negative input is increased by **exactly one** 256-unit width and returned;
a nonnegative input repeatedly subtracts 256 until it is below 256. The
subtraction loop stores each intermediate to a `double` stack slot, while
the negative addition returns directly in the x87 register stack.

Thus `-257` maps to `-1`, while `512.5` maps to `0.5`. The behavior is not a
general modulo operator. Unordered absolute-value comparison also takes
the zero branch for a quiet NaN. Positive infinity never leaves the
subtraction loop; this source port claims finite gameplay coordinates.

The adjacent `0x0040DF50` clamps a double Y against the world height.
Values below zero, including unordered NaN comparisons, return zero.
Otherwise it returns the input when it is strictly below height, or
`height-1` when it is at or above height. The height getter reads world
`+0x418`. A zero height and nonnegative input therefore return `-1`,
which the source preserves.

behavior, multiple positive wraps, and a quiet NaN. An owned x86 helper maps
the original X routine, its wrapper, CRT finite path at `0x0049C8F4`, FPU
control helper at `0x0049FC56`, and referenced constants. All 10,018
finite-input comparisons matched the C++ result. The CRT helper bodies are
