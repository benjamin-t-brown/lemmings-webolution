## Read from the machine code

`0x00430F4D` starts at the first node of retained actor list `0x004C88D0`,
clears the output array, and walks nodes in order. For each actor it calls
`0x00430C9C`. When the returned subbox index is not `-1`, it calls
`0x00406A00`, sign-extends the 16-bit result, and appends it to the output.
If the byte flag passed to the routine is zero, it returns after the first
match; otherwise it collects every match.

`0x00406A00` reads a word at actor `+0x3A`. `0x00406650` frees a non-null
array buffer, zeroes capacity only in that case, then invokes `0x00406AE0`
to set count to zero. `0x0041BC10` appends 32-bit values to an array with
count `+0`, capacity `+4`, growth step `+8`, and data pointer `+0xC`.
At capacity it adds the growth step, allocates `capacity * 4` bytes, copies
the old count of integers, frees the old buffer, stores the value, and
increments count. Its allocator is the game's Visual Studio 2003 `operator
new` path at `0x0049C1A8`; the release path reaches the CRT heap through
`0x0049C13D` and `0x0049E340` (REA analysis Evidence
`ev_4d423ddfa005b11f7baede2e31c71dda43d5e3c9e4bddb2da09f195cc77a9c64`,
`ev_3a745498bee3add32f46d6e16820d16099df399a896f79832928bddfea172255`,
`ev_373a103c4f5273f85f0900264d47adc7a75d0cad7a81e0ccd0e95e35b4f94bcd`).

## Scope and unknowns

The source ports the observed iteration, signed IDs, reset, and growth
behavior. It adds a guard for invalid growth headers that the original
does not have; the original's behavior there would be unsafe. Tests cover
preexisting output, first-only and all-matches modes, signed IDs, growth,
and reset. An owned x86 helper maps the original collection, array, list,
and subbox routines at their native addresses. Calls into the unrecovered
CRT allocator chain at `0x0049E88A` and `0x0049E340` are routed to the helper
process's `malloc` and `free`. With that adapter, 20,000 comparisons of
count, capacity, growth, and values matched the C++ result in first-only and
all-matches modes. This is an offline original-byte check of the collection
path, not a live-game measurement or validation of the original allocator.
The meaning of the actor ID and caller's use of the collected array remain
to be recovered.
