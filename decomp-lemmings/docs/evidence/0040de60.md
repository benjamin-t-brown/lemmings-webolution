## Read from the machine code

The accessor masks X with `0xFF` (`0x40DE6A`), clamps Y to the stored
height at world `+0x418` (`0x40DE78` through `0x40DE9C`), then computes
`(Y << 8) + X` and calls `0x00404D10` on the array header at world
`+0x41C`. That helper returns `data + index * 4`, where the data pointer
is array `+0xC` (world `+0x428`). No bounds check or cell read occurs in
either routine. The return pointer remains in `EAX` through the outer
function's `RET 8`, despite Ghidra's `void` signature for `0x0040DE60`.

X wraps modulo 256. For positive height, Y below zero selects row zero and
Y at or above height selects the last row. A zero height also produces row
zero. Extremely invalid dimensions and a buffer shorter than the indexed
range are outside this port's supported inputs; the original has no safety
check for them.

## Verification and limits

Both x64 and x86 MinGW unit tests pass. An owned 32-bit helper maps the
verified bytes for both routines at their original virtual addresses and
compares the returned pointers with `collision_cell` for 20,248 cases,
including negative and wrapped X, clamped Y, heights -2 through 5, and
deterministic random coordinates. All matched. The helper retries when
Windows address randomization occupies its required low virtual address.
This is an offline original-byte comparison, not a live game observation.
The full world object, cell meanings, and mutation paths are separate work.
