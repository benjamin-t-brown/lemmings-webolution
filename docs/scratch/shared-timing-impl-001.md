## 2. Design (what is and is not claimed)

### 2.1 Pass and update structure (STATIC, from gate-cadence section 1.2/1.3)
`advanceElapsedMs(dtMs)` is one original-style frame pass: advance to each due 1000 ms level-clock event, run one world update with `dt = segmentMs / 1000.0`, fire the event, repeat, then a trailing update with the remainder (possibly 0). A boundary that lands exactly on the end therefore yields the first full segment and a trailing zero-length update; `dtMs == 0` still yields one zero-delta update. The level clock is advanced before each update, as in the frame loop. `levelSecondEvents()` counts the 1 Hz event (`0x444D1E` / `0x4458B0`); it is the same clock the HUD/timeout state derives from, so no second countdown exists.

### 2.2 Order inside an update (STATIC, lever-timing section 1)
hatch release -> every lemming (list order) -> lever contact. Lever contact (`stepLeverContacts`) runs once per update after all lemmings moved, takes the first accepted lemming in list order per lever (so one lever activates at most once per update), applies the traced `cooldown -= dt` / `fire only if cooldown <= 0 after decrement` / reload rule, and writes `Lever::state := pull facing`. The legacy in-`step()` lever arm is disabled during an explicit update, so the two semantics never both run in the native route.

### 2.3 Movement: what consumes variable dt and what does not
* **Consumes dt (existing D1n `continuousStepperClock` contract, forced on for this entry):** `stepFaller`, `stepWalker` (including the speed-pad double step and the same-update walker handoff), the continuous release model (arm clock, countdown, spawn budget), and the completion slice. The lattice unit stays the measured `tickDtSeconds()/speed`; the budget is `dt + carry`. A legacy `tick()` computes the same numbers as before (dt equals the tick).
* **Cannot safely consume variable dt, kept on the measured 5 Hz level-clock boundary (NOT converted, NOT claimed faithful):** Climber, Hoister, Floater/umbrella bookkeeping outside the fall loop, Builder, Basher, Miner, Digger, Shrugger, Exploder, Bounce, Teleporting, Drown, Splatter, Blocker re-check, bomber fuse, speed-pad timer, frame counters, exit/hazard/teleport/pad detection, and the integer-tick release model. These run their existing per-tick `step()` once on the update that reaches a `msPerTick()` boundary of the level clock. That is the pre-existing measured 5 Hz quantisation, not a new gate constant. Release/digger/skill algorithms and rates were not retuned.
* **Consequence (bounded limit):** for lemmings in those states, exit/hazard/pad/teleport tests and skill steps happen at 0.2 s level-clock boundaries, while walkers/fallers move continuously between boundaries. This is a hybrid; it is not full D1/D3 fidelity.

### 2.4 Input contract (`RuntimeSimState::advanceElapsed`)
Integer ms with carry; 100 ms cap using the original comparison (`100 < dt` clamps, exactly 100 does not); discarded stall time is dropped; pause drops input and carry; first unpaused frame carries only its own delta; seven passes reuse the same integer dt; completion stops remaining updates/passes once the existing end phase reaches Results; a fresh `World` + fresh `RuntimeSimState` is a reload (level clock, event count, lever state and carry restart).

### 2.5 Explicit non-claims (reference limitations preserved)
Startup-zero forced-delta flag (`[0x4E33BB]`) is not proved immutable; the two event-insertion triggers (`0x413DF9`, `0x41527B`) and event-list reload clearing remain unresolved and are not modelled; only the proven 1 Hz level event is implemented. Zero-dt lemming behaviour in the original is not traced; in the clone a zero-delta update moves nothing but still evaluates contact (contact is dt-independent per STATIC lever-timing section P). The HUD seconds formula (`timeRemainingTicks() / ticksPerSecond`, integer truncation, `runtimeHudValues`) is unchanged and was not retuned. By arithmetic on that formula (not an original measurement) it drops from L to L-1 after the first 0.2 s tick, whereas the traced 1 Hz event decrements at 1000 ms; that display-vs-event offset is pre-existing, is not reconciled here, and the shared clock exposes `levelSecondEvents()` for the later reconciliation. Timed Armageddon, release/digger timing, clipping/controller/capture remain parked. No gate receiver, mask write, fluid or `FluidGate` state was added: lever activation still only toggles `Lever::state`.
