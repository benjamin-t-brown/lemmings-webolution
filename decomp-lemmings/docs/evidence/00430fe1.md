## Read from the machine code

Both setters store wrapped X coordinates at gadget offsets `+0x48` and
`+0x60`, clamped Y coordinates at `+0x50` and `+0x68`, and Z coordinates at
`+0x58` and `+0x70`. The first setter writes Z as `0.0` and `1.0`; the
second copies caller-supplied Z values. Both compare stored maximum Y to
minimum Y with x87 `FCOMP` and test `AH` bit zero. When the maximum is less
than the minimum, they swap just the Y doubles. An unordered comparison also
sets that bit, although ordinary input NaNs are already mapped to zero by
the Y clamp. X and Z are not reordered. See [coordinate evidence](0040dec0.md).

The caller at `0x004338C2` receives two pointers to 16-byte XY values and
an integer mode. Its `0x004017F0` helper merely copies six 32-bit words to
a temporary XYZ value; no arithmetic occurs. Mode 2 calls the full XYZ
setter with Z `[0.5, 1.0]`. Mode 0 first calls it with `[0, 0.5]`, but then
falls through to the XY setter, which overwrites Z with `[0, 1]`. Every
other mode also calls the XY setter. The recovered source expresses the
final state for finite coordinates.

## Verification and limits

The exact source bytes above were checked against the reference executable and
the x64 and x86 unit tests cover wrapping, clamping, Y reversal, and mode
selection. An owned x86 helper maps the original setter, coordinate, CRT,
and constructor bytes at their native addresses. Its 15,030 finite-input
comparisons across the three setters matched the C++ source byte for byte
in the six stored bounds doubles. This is an offline original-byte check,
not a live-game observation. The original uses a global world object at
`0x004C6A10`; the source passes an explicit world head to keep the behavior
testable. Infinite X and exceptional CRT handling remain outside the claim.
