## Runtime change and selection order

`src/app/main.cpp` `runApplicationLeg` calls `TubeScene::build` at line 445,
passing `args.highDetailTiles`. Its presentation callback calls `scene->render`
at line 612. `TubeScene::build` validates tile names with the unchanged
case-sensitive `parseTilePosition`, then its existing `loadBlock` now:

1. Forms the HI bitmap name when high detail is selected, or the unsuffixed
   bitmap name when explicit low detail is selected.
2. For high detail only, calls `AssetLibrary::contains` on the HI candidate.
   Absence selects the unsuffixed name before decoding.
3. Calls `loadTexture` exactly once. Read, packed-payload, BMP and alpha errors
   from an existing HI entry remain errors; they do not cause another attempt.
4. Retains the existing `toTexture` conversion, position, insertion order and
   tile counts on success, and the existing tile-qualified diagnostic on error.

Each candidate resolves independently through the unchanged patch-over-base
overlay. A base HI bitmap wins over a patch unsuffixed bitmap; a patch HI bitmap
overrides base HI. Explicit low detail still requests the unsuffixed bitmap
directly. There is no new quality classifier or Lo selection.

Retained tiles are consumed by `findTile`: the wall pass at lines 498-499 skips
absent tiles and submits loaded textures through `drawQuad`/`Raster::triangle`.
The cell mesh pass at lines 539-541 and the application route's
`tileFor`/`drawRouteQuad` at lines 600-610 likewise skip absent tiles and submit
the retained texture. No renderer implementation or public API changed.

Before, a valid unsuffixed-only outer or inner tile was omitted under default
high detail. After, that tile reaches the existing rendering path. This is a
source-derived scenario demonstrated using synthetic data, not an observed
retail-frame repair.
