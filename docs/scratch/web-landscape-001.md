# Phone landscape play

The November 23 mobile request V1 applies to the shared web frontend for every installed level. The previous Start handler opened the canvas at the saved window scale and accepted input in portrait. The phone warning was the only phone-specific behavior. This is a browser feature for the clone. [Mobile request](../playtest/2026-11-23-mobile-request.md)

In `src/web/webolution.html`, Start uses the existing `isMobileDevice` test and requests fullscreen on `main` in the click gesture, then requests `screen.orientation.lock('landscape')`. The same click starts `Module.ccall('main')` without waiting for either browser API. The portrait media query controls the prompt when fullscreen or locking is unavailable or declined. The fullscreen element contains both the prompt and the canvas. [Page source](../../src/web/webolution.html#L197) · [Screen Orientation specification](https://www.w3.org/TR/screen-orientation/)

In portrait the prompt covers the entire play area, the canvas becomes inert, and window capture blocks new input and movement from an already active touch. Releases can clear SDL's held state. The page sends window blur and focus through SDL's existing focus callback. `runApplicationLeg` uses that path to cancel held gameplay controls and camera drag. The level simulation keeps running, as the prompt states. In landscape the page centers the 4:3 canvas and hides other page content. Phone play applies the viewport zoom limits and CSS gesture suppression. Emscripten computes target coordinates from the canvas rectangle and SDL scales them to backing pixels for mouse input or normalizes them for touch. The page still forwards the original mouse client coordinates. [Level focus handling](../../src/app/main.cpp#L1350) · [Canvas mapping](../../src/app/SdlWindow.hpp#L100)
