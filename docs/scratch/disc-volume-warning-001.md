# CD image volume warning

Playtest 25 Q3 added Windows CD-image startup. The `windows-release-001` review made `Iso9660::readVolume` reject any image with fewer complete physical sectors than a primary or recognized Joliet descriptor declared. That check ran before the importer looked up the required directories and files, so trimming only the unused tail prevented startup. [Playtest 25](../playtest/2026-11-21-playtest-25.md) · [Prior release report](windows-release-001.md) · [Prior reader](../../build/disc-volume-warning-001/DiscGameData.cpp.before)

`runApplication` → `locateGameData` → `installDiscGameData` now carries the volume-size mismatch through extraction and prints one stderr warning after successful validation and cache publication. Directory reads and the selected `LEMPATCH.EXE` or root `PATCH.BOX` and `LEMMINGS.BOX` copies still require complete physical sectors. `AssetLibrary::openRequired` validates the box headers and layout. Unfamiliar hashes retain their existing warning, and a failed import removes its staging output.

The retained archive.org image has 329,058 raw sectors, 232 more than the 328,826 declared. Its base is at LBA 22,434, root patch at 180,517, and patch installer at 207,663. The volume warning is clone startup policy. Original-game behavior is unverified, and a physically trimmed retail rip remains for human playtest. The promoted replays all use loose archives when run with `--game-dir`, which bypasses disc import. This change affects startup before level selection, so no replay route applied. [Disc descriptor bytes](../../build/windows-release-001/revision/retail-volume.log) · [Disc extents](../../build/disc-unrar-001/disc-layout.txt)

- The legacy `disc_game_data` test passed with all three trimmed layouts extracting byte-identical boxes and three stderr warnings. The existing tail cuts previously had to fail. A cut through the base still fails, now at the file extent check. A cut through the primary root directory and invalid patches also fail and leave only their input images. The retail extraction matched both expected SHA-256 values, and the fixture-absent run passed its synthetic checks with the expected skip.
