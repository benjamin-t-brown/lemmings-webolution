## Read from the machine code

The object supplies center X and Y at `+8` and `+0x10`; the input is a
pointer to three doubles. The routine recomputes `12.0 / 2.0` on the x87
stack for each XY face. It accepts inclusive lower and upper XY faces at
center ±6, then Z in inclusive `[0, 1]`. The lower XY tests accept an
unordered x87 comparison; the upper XY tests reject one. The Z lower test
rejects unordered, so an input NaN Z cannot pass the final upper test.
No cylinder normalization occurs in this routine. Its caller at
`0x0041DF31` walks retained actors when a timer expires and clears an actor
flag at `+0x5E` for points satisfying this predicate; that wider behavior
is not yet ported.

`0x0041DD4B` reads a byte at object `+0x98`. If zero, it sets that byte
to one and copies a caller-supplied double into `+0xA0`; otherwise it leaves
the timer unchanged. `0x0041DF31` calls it with approximately 0.6 seconds
after a retained actor first enters a local gadget box.

`0x0041DD86` reads the global actor-pointer array at `0x004C89A8`.
Each actor has a position at `+8`, enabled byte at `+0x38`, and timer state
at `+0x98` and `+0xA0`. The routine skips disabled actors and those with an
active timer. It subtracts actor position from the supplied origin into a
double XYZ temporary, computes the dot product of that difference with
itself on x87, stores the squared length to double, and compares it to the
supplied radius squared (also stored to double). A strict less-than or
unordered result arms a 0.1-second timer through `0x0041DD4B`. The 0.1
constant is at `0x004B0DB8` (REA bytes
`ev_857fcc9628561f76efdba4bf10efa0989489e70145c53aad65a610ad20c82ab1`,
offset `ev_feb4cc0ef91546f5a706c9e5609681a6b303a3d0f890fd1a4af6af7c0cbbbce7`).

`0x0041DF31` reads the timer at `+0x98`/`+0xA0`. If disarmed, it calls the
first-actor-in-subbox routine and arms 0.6 seconds when an actor is present.
If armed, it subtracts elapsed time, stores the result, and returns one
while the result is nonnegative. On a negative or unordered result it calls
the still-unrecovered terrain effect `0x0043F510`, arms nearby eligible
actors within radius 12 through `0x0041DD86`, and walks the retained actor
list. For each actor in the rectangular region it writes zero to byte
`+0x5E`. It then returns zero. The 0.6 constant is at `0x004B0DB0`
(REA bytes `ev_5be4c524b623dee23fed6f38b0f744e137dddf3e353f338d7e07804678190c16`,
offset `ev_0e40c9a57c267a0c1b0bc6f1e8393a6ead1f8c10e27562348c7cbfadc6eb0ef9`).

## Verification and limits

An owned x86 helper maps the verified original routine and four constants
at their native addresses. Its 10,237 special-value, boundary, and numeric
comparisons to the C++ source passed. The x64 and x86 unit tests pass too.
The same helper compared 10,000 one-shot timer state updates to the original
bytes with no mismatch.
It also mapped the original actor-registry, vector math, eligibility, and
timer routines, then compared 5,000 constructed actor lists to the C++
nearby-timer effect with no mismatch. The source receives the actor pointers
explicitly instead of reading the native global. Registry mutation,
insertion, and removal are not covered.
For the state update, the owned helper also maps the original retained-list
and subbox routines and replaces the call target `0x0043F510` with a counter
adapter. Its 5,000 comparisons matched return value, timer state, effect
invocation count, nearby timers, and retained actor flags. The terrain effect
itself, including terrain changes and visual objects, is not recovered or
verified. The source exposes that call as a callback, and represents the
subbox and timer fields as two explicit views of the original object.
This is offline original-byte evidence under the helper's FPU mode, not a
live-game measurement. The exact object class and meaning of the actor flag
remain unknown.
