# disc-unrar-001 · Disc patch extraction and 1.0 data

The November 20 web-release task adds a clone-side RAR 2.0 reader for `LEMPATCH.EXE`. The reader follows the public block and codec descriptions. The disc image independently matches all three staged extents. The SFX is 5,447,696 bytes, SHA-256 `e958f81c3ac2c998b331c3f5450ea3816ecb7c3ec6cf06074830dd503f080d39`. Its RAR marker is at `0x4620`, its file headers are at `0x4634` and `0x48db6`, and the last packed member ends at EOF. [RAR 2.x wire description](https://zxpress.ru/en/ezines/inferno/04/technical-documentation-of-rar-2-x-archive-format-block-structure-header-types-archive-processing) · [Codec and audio description](https://github.com/bitplane/rar-research/blob/master/doc/RAR15_40_FORMAT_SPECIFICATION.md#16-compression-algorithm-rar-20-unp_ver-20) · [Disc layout and hashes](../../build/disc-unrar-001/disc-layout.txt)

`lrtool unrar` and the pre-main Wasm export `webolution_extract_rar20` both call `extractRar20File` → RAR header scan → solid-chain decode → CRC-checked file replacement. The export takes the archive path, exact entry name and output path in that order. The reader discards solid predecessors after checking their CRCs. The file adapter accepts archives up to 64 MiB, and the decoder bounds each member at 64 MiB and each extracted chain at 256 MiB. It supports single-volume, unencrypted RAR 2.0 compression and legacy stored members. The export expects the SFX already in the Emscripten filesystem. Audio coverage uses a synthetic two-channel stream with predictor and table changes across a solid boundary.

The CLI and legacy test verified both CRCs. The emitted `patch.box` SHA-256 is `a393a45e71d797fc5b646a9a235d1f64298129f378c6f4b79f47ec773d00de53`. The legacy test passed its in-memory cases and reported a clear skip when run with an absent disc fixture. The Emscripten release linked against the registered SDL2 cache after pointing `EM_PORTS` to the SDK's prepared port. The Node probe called the export before `main`, matched the digest, and preserved the verified output on missing-name and truncated input errors. ## 1.0 compatibility

The existing `runApplication` → `AssetLibrary::open` / `AssetLibrary::read` → `FrontendSession::create` and `loadRetailLevelReport` paths accepted both sets of assets. Patch entries take precedence over base entries. The 1.0 directory uses a hard link to the installed `lemmings.box` and a copy of the disc `patch.box`. `lrtool info` found valid contiguous box layouts, `lrtool levels` read the map, and `lrtool lvlstats --csv` parsed all 102 compiled levels. With a private save path, `test_frontendentry` selected Just Climb (`MM_CLIMB_002`) through the production frontend. The unchanged sweep reported 102 completed nodes, each with a visible settled frame. No loading fix was needed. - The 1.0 patch has 203 entries and 1.1 has 311. `PATCH.LST` and the French, German, Italian, Polish, Spanish and UK string tables grew. The 1.1 patch adds 97 overrides for `VH04_JC1`, the compiled level plus 96 cylinder textures. After applying the overlay, the level changes from 897,007 to 873,747 bytes. Two outer cylinder textures differ from their 1.0 base versions, `OUT_VH04_JC1_5_2.BMP` and `OUT_VH04_JC1_5_2HI.BMP`. The other 94 textures in the override set match the base bytes.
