# Window size in Options

The November 19 request adds an in-game **Window size** picker as a clone addition. Playtest 6 V9 reported that the window was small. The earlier fix exposed integer scaling through the desktop command line, and the browser still capped the picture at 1280 CSS pixels. The setting applies across levels, including **Just Climb** (`MM_CLIMB_002`, node 0). [Playtest 6 V9](../playtest/2026-11-15-playtest-6.md) · [Incoming sources](../../build/window-scale-option-001/git-show/)

Main-menu and in-level Options share `SoundMenu` and `FrontendSession`. The arrows and Left/Right step through the values. Clicking the label or pressing Return while focused on it advances the choice. Accept commits and Escape discards. The existing in-level O shortcut also commits when it closes the pause menu. `finishSoundEdit` writes through the injectable `SaveSink`. Version 3 of `SoundSettings.dat` beside `SavedGame.dat` stores `windowScale`, where 0 selects Auto or Fill and 1–3 select a fixed scale. Versions 1 and 2 load with the platform default. A failed write retains the earlier file and retries as part of a later Accept. Web uses the existing IDBFS mount and replacement policy. [Options session](../../src/app/FrontendSession.cpp) · [Sidecar codec](../../src/save/SoundSettings.cpp)

Both event loops pass the accepted choice to the shared `SdlWindow` after processing the current SDL event batch. Desktop Auto takes the smaller of the usable client width divided by 640 and the usable client height divided by 480, rounded down after accounting for window decorations. It can select 4x or higher. The fixed choices remain 1x, 2x and 3x. An oversized fixed selection stays in the sidecar and the row shows the scale that fits. `SDL_SetWindowSize` and `SDL_SetWindowPosition` update the same window and renderer, and `gameCoordinates` uses the applied scale. The browser sets `data-window-scale` for the exact fixed CSS sizes or an uncapped 4:3 viewport fit. SDL maps its canvas rectangle to game coordinates, and the page refreshes the cached pointer position before a mouse button event after scrolling or a resize. Render resolution remains 640×480 on both platforms. [Desktop presentation](../../src/app/SdlWindow.hpp) · [Scale fit](../../src/app/WindowScale.h) · [Browser page](../../src/web/webolution.html)

`runApplication` uses the CLI's existing frontend routing to classify diagnostics. Non-frontend paths, including unbounded `--direct-level`, use 1x by default, as do bounded, capture and observer runs. An explicit `--window-scale` takes precedence for that run and leaves the stored setting intact.
