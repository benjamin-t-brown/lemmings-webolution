# Touch assignment, precision cursor and hatch rate

**needs_review.** The November 23 mobile request V3 followed the V2 touch camera pass. The V2 level adapter deferred scene taps to a synthetic left click on lift, expired long scene presses and treated hatch taps as mouse decrements. That source path explains the missing touch-down assignment, precision hover and bidirectional hatch gesture. V3 came from the mobile request ledger. [Request and decisions](../playtest/2026-11-23-mobile-request.md) · [Incoming source and Git reference](../../build/touch-assign-001/entry/)

`runApplicationLeg` classifies the first SDL finger-down using the displayed picker and left-click hatch precedence. The shared assignment path calls `World::assign`, records the resolved actor and skill, drains cues and resumes ordinary pause on success. A continuing swipe takes the existing camera drag path. An empty hold enables `TouchInput`'s offset cursor, which supplies the same renderer and hover coordinates as the mouse. Lift picks at the final offset point and assigns only an eligible actor. A second finger dismisses precision and can start a pinch. The provisional hold is **180 ms**, with an **8-pixel** drag slop and a **28-pixel** offset above the finger in 640×480 presentation space. [Level input](../../src/app/main.cpp#L1603) · [Gesture recognizer](../../src/app/TouchInput.cpp) · [Task diff](../../build/touch-assign-001/task-only.patch)

After a hatch hold, vertical motion beyond a provisional **12 presentation pixels** starts the shared release-rate hold in the corresponding direction. The renderer and rate control keep the touch-down point on the selected hatch. A return to the neutral zone or finger-up stops repeats. The shared path applies one immediate step, repeats at **20 ms** intervals, clamps to that hatch's limits and records effective rate commands through `ReplayRecorder::commands`.
