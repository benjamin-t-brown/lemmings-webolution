# `0x004432C1`: compiled level loader prefix

## Identity

All addresses refer to the installed x86 reference executable, SHA-256
`32675bdb49866e76502713251fdfd2b09078c2481c72ca22ff68ebf4b3737a2f`.
The 4,372-byte analyzed loader body starts at file offset 275137 and has
SHA-256 `28e705623c5eda58d87e75f168d9fe091578b7b0ff5a0a50b4247c1fa7410e00`.
REA function analysis `ev_8d9fa6a1e027223845bdf5df37504c4b003200a957f7f846b1a37da755e946f5`;
file-offset mapping `ev_a50d82e63621b8ca8e5aee6d7280d0931dd922d71ec4cf4ddf4d7aed6122803c`.
The verifier pins this body, the small read helpers, and the marker bytes.

## Observed prefix sequence

At `0x00443318`, the loader passes the pointer at `0x004B15E0` to
`0x0047DA37`. The pointer resolves to the NUL-terminated string
`"Level 23"` at `0x004C0008` (bytes `ev_03c4eb84cd587399ad894838a00d62168902d4932af2c3d88894f86f6e48922c`,
`ev_ed92e9a373f994324c39447984ac931f97cca08ede29f7f0a1fdaca7db46d8e3`).
`0x0047DA37` reads a length-prefixed string through `0x0047D940`,
compares it with the expected marker, and checks that it is nonempty.
The caller does not inspect its return value before proceeding. A marker
mismatch therefore does not itself stop this loader path.

`0x0047D940` first calls `0x00402560` for a four-byte length, then calls
`0x00402540` for each byte up to its buffer limit, terminates the local
string, and consumes any remaining bytes in that limit path. When the
declared length exceeds the supplied limit, it only writes an empty
string and returns; the declared payload remains unread. The helper
bodies were analyzed as `ev_aaba45f49f0a856bc8a7fdf9691cf3998f96e705d8a89ddad44b0f73b17e9b6d`,
`ev_c9af2bd090def6726830708478c491f733cf6b9080868f86d56869b3aaf530e2`,
and `ev_e50b7c8964b76be97986fab0785311bf31b4cc073fa8405762ae7d69585ba232`.
The primitive helpers copy one or four bytes from the stream into a local
value. Their deeper read target at `0x0047EEF7` calls a CRT-like file read
through the stream's handle at `+0x118` and increments a byte count at
`+0x120` (`ev_b18bc0e83551518601ea4d67a12753b5ca3d3cbc4734a47f05d8a39b025089e4`).

`read_level_string` ports `0x0047D940` for complete in-memory inputs with
a positive destination capacity. An offline x86 oracle maps the verified
bytes of `0x0047D940`, `0x0047DAC8`, `0x00402560`, and `0x00402540` at
their original addresses. It replaces the underlying stream read at
`0x0047EEF7` with an in-memory adapter. Across 5,000 generated lengths,
capacities, and byte sequences, the entire destination buffer and final
stream cursor matched. This includes strings shortened to `capacity-1`
and declared lengths exceeding capacity. Truncated physical streams and
invalid destination pointers are outside the source function's claim.

After the marker call, the loader reads the stream member at `+0x10`
through `0x0047EE27`, then makes five consecutive four-byte reads at
`0x00443334` through `0x00443371`. It multiplies the first value by
`0x3A`, adjusts a global offset, makes a sixth four-byte read at
`0x004433B3`, and reads four one-byte flags at `0x004433DF` through
`0x004433FD`. These are observed read order and arithmetic only; the
field names, signedness, and file-format meaning are not established.

## First three resource-name tables

The loader calls `0x00445C10` and then `0x00445EB0`. Each helper reads a
four-byte count through `0x00402560`, then that many strings through
`0x0047D940`. The first body is 347 bytes at file offset 285712,
SHA-256 `4cc15d1c11d5770fe5ca589a62937af61839720ec8251e59203df1af69eda249`
(REA `ev_6d6acf0212e3ebe5470da5fc34cc4d00af71d5f34c7c8c97bc9f4feb42357f6e`).
The second is 347 bytes at file offset 286384,
SHA-256 `c689f070fa2646eb9fef350976a937ca5f84e44b1007809aea614c0f2145dc7d`
(REA `ev_e30f4863f19068afe2c23008e04fc37af88553b3ef568c2a2dbf62c93d11ed8e`).
Both routines also allocate storage, look up existing names, and avoid
duplicates in their destination tables. That object behavior is not
represented by the file-read port.

The next call, `0x0042FE1F`, sets a global mode byte and delegates to
`0x00430420`. The latter reads a count and calls `0x004304A0` once per
entry; each entry begins with another `0x0047D940` string. The exact

The resource lookup and optional name rewriting inside `0x004304A0`
remain outside the file-read port.

`read_compiled_level_prefix` reads the header, the first three name tables,
the following object count, the first complete serialized object when present,
and fourth and fifth name tables plus one bounded string.
Across all 105 installed `.LVL` entries, the first table count equals
header field zero. The first tables contain 11,652 names in total and the
second tables contain 84,809; the longest observed name is 56 bytes.
Every third table in these fixtures is empty. The following object count
is one in 100 levels and zero in five. The optional installed-fixture test
compares all parsed name sequences, counts, and final byte positions on
x64 and x86. It uses the user-owned archives in place. This is a fixture
comparison, not execution of the original table-loader functions.

## First class-one polygon

`0x00469578` reads a byte allocation length and delegates to `0x00469BAF`.
That reader checks a `PolyList 09` marker, reads type, record count, and an
additional four-byte value, then dispatches by type. Installed records use
type four, whose dispatcher `0x00469B27` calls `0x0046A0F0` for each record.
Each record is serialized as one four-byte value, three doubles, one double,
and three repetitions of a four-byte value plus two doubles. The read path
runs through `0x0046AF50`, `0x0046AF80`, `0x00479F3A`, `0x0047A0C0`, and
`0x004821DE`. After these records, `0x0046BB73` reads twelve doubles via
`0x0046BEA0` and `0x00482118`, a string via `0x0048252D`, two more doubles,
then a count of nested objects. Exact analyzed body lengths, file offsets,
and SHA-256 digests for these twelve functions are pinned in

`ev_80b2d98a8b56211232c9b23b8b86b4d4fdd279b22f3396defa41bc47ad6233c4`,

`ev_1a80f092eb4e9470ed3c97dbb54b1ef8f0b96030b5be65e5ba0b2e181bcd5c80`,

All 100 populated level fixtures use one polygon, allocation length 1360,

The fixture test compares both serialized class-one nodes and the byte cursor
after the object on x64 and x86. It does not run the original loader or

## Fourth name table

Immediately after the object list, `0x004432C1` calls `0x00445A10`, which
reads a four-byte count and that many length-prefixed names. Its 347-byte
body starts at file offset 285200, SHA-256
`671052f5de3aab26749fb34fb4a2674d1aa8f00e09b512c5cf30809d001643f2`
(REA `ev_1cffb619b1085b17e22956fc207d2a7c50d7bd8c8e98d1b6e88e1b2468bd92f5`).
The C++ parser reads the file data and leaves deduplication and resource
lookup to later work. The 105 installed levels contain 117,573 names in
this fourth table; the fixture test compares the sequences and final cursor.

## Limits

This is a static map of the loader's prefix, not a level decoder or a
validated file-format specification. The installed game's `.box` archives
contain 105 compiled `.LVL` entries, and all 105 begin with the observed
length-prefixed `"Level 23"` marker. The archive index and one level header
are recorded in [the archive note](box_archive.md). Later allocations,
terrain data, gadget records, and class-specific object construction inside
the loader remain unrecovered.
