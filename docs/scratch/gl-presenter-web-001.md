# WebGL2 presenter

Phase 2b implements the browser half of the November 24 OpenGL request. The Start page offers software by default and WebGL2 as an opt-in. The Start gesture passes the choice to `runApplication` through the existing Asyncify `main` call. `SdlWindow::ensure` logs the requested and actual renderer once. `runFrontendWindow` and `runApplicationLeg` deliver the same CPU-composed menu, map and level images used by the native presenter. [Playtest request](../playtest/2026-11-24-opengl-request.md) · [Plan](../OPENGL_PLAN.md)

`WebGlPresenter` requests WebGL2 on the canvas-owning thread, checks the returned ES 3.0 version and framebuffer, and compiles the common shader with the ES precision preamble. It uploads the top-down 640×480 RGBA image for nearest presentation. The logical comparison target is RGBA8. `glReadPixels` reads it before canvas compositing, and the presenter flips its rows into top-down order. The GL path runs CPU raster bands on the context owner and adds no worker threads. [Presenter](../../src/web/WebGlPresenter.cpp) · [Shared shader](../../src/app/PresentationShaders.h)

The WebGL canvas overlays the original SDL input canvas. That canvas continues to own focus and input and is available for Canvas 2D if initialization fails after WebGL has already claimed its own canvas. During play the next submission checks for context loss, releases the context, and presents the same CPU frame through SDL software on the existing window. This phase keeps software for the rest of that session after a loss. The change stays inside presentation, below the selected level, pause state, audio, IDBFS lock and animation-frame loop.
